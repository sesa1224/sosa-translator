# MV/MZ 번역 작업실 기획서

작성일 2026-11-13. 화면 시안: https://claude.ai/artifact/SjH7itvmTbvVSMf8Hfq4oG

표시 규칙: **[확정]** 은 사용자가 정한 것, **[내 선택]** 은 Claude가 정한 기본값이라 바꿀 수 있는 것.

## 1. 왜 만드는가

지금은 게임 폴더를 Claude에게 통째로 넘기고, Claude가 구조 파악, 언패킹, 텍스트 찾기, 번역, 재삽입, 패키징을 전부 토큰을 써서 한다. 판단이 필요 없는 기계적인 일에 토큰과 시간이 들어가고, 대화가 바뀔 때마다 게임을 다시 파악해야 한다.

이 프로그램은 기계적인 일을 전부 맡고, Claude에게는 판단이 필요한 조각만 넘긴다.

- 프로그램이 하는 일: 풀기, 추출, 검색, 형식 검사, 재삽입, 이미지 찍기, 빌드, 기록
- Claude가 하는 일: 용어집과 말투 지침 작성, 번역, 검수, 버그 원인 판단, 식별자인지 판단, 이미지 속 글자 읽기

## 2. 목표와 범위

### 목표 [확정]
- RPG Maker MV, MZ 게임의 일본어 → 한국어 번역 작업 전체를 한 프로그램 안에서 한다. (언어 방향은 [내 선택]. 다른 언어도 설정으로 바꿀 수 있게 만든다.)
- 번역 대상: 대사와 선택지, 데이터베이스, 플러그인 설정과 플러그인 코드 속 문자열, 이미지 속 글자.
- 번역 외 작업: 이벤트 흐름 버그 수정, 기능 추가. 예: 이벤트1이 끝나면 이벤트2로 넘어가게 하기, 특정 장소에서 특정 행동을 하면 다음 시간대로 넘기기.
- 게임이 업데이트되면 바뀐 부분만 다시 작업한다.
- 프로그램 안의 채팅창에서 Claude에게 말로 시킨다. 연결은 Claude CLI를 쓴다(사용자의 Claude 구독 사용).
- 빌드 결과물은 바뀐 파일만 묶은 패치 zip이다. 패치노트가 자동으로 기록된다.

### 범위 밖
- Unity 기반 RPG Maker Unite, VX Ace 이하 등 MV/MZ가 아닌 엔진 [확정]
- 번역 자체의 자동화(기계번역 엔진 연결). 번역은 Claude 모델이 한다 [확정]
- 게임을 exe 하나로 다시 뭉치기 [내 선택]
- 제작자가 따로 건 특수 보호 해제. 못 풀면 알리고 멈춘다 [내 선택]
- 음성, 영상 속 글자

### 이렇게 되면 실패
- 원본 게임 파일이 수정된다.
- Claude가 게임 전체를 읽어야만 일할 수 있다.
- 식별자(코드가 이름으로 찾는 문자열)가 말없이 번역되어 게임이 깨진다.
- 파일이 빠진 패치가 배포된다.
- 새 대화를 시작할 때마다 Claude가 게임을 처음부터 다시 파악한다.

## 3. 핵심 구조: 원본과 층

게임마다 프로젝트 폴더가 하나 생긴다. 원본은 읽기 전용이고, 한 일은 층으로 따로 쌓는다.

| 구성 | 내용 |
|---|---|
| 원본 | 풀어낸 게임 그대로. 버전별로 보관. 수정하지 않음 |
| 번역 층 | 원문 → 번역 표. 파일 위치가 아니라 원문 기준으로 저장 |
| 수정 층 | 버그수정, 기능추가를 "원본 대비 바뀐 점"으로 기록 |
| 이미지 층 | 이미지마다 작업 지시서(영역, 문장, 폰트, 크기, 색) |
| 용어집 | 용어 목록, 말투 지침, 형식 규칙 |
| 기록 | 빌드 이력, 패치노트, 확인 필요 목록, 작업 기록 |

빌드 = 원본 + 번역 층 + 수정 층 + 이미지 층.

저장 형식은 만드는 사람이 정하되, 사람이 열어서 읽을 수 있고 프로그램이 죽어도 내용이 남아야 한다.

## 4. 기능

### 4.1 가져오기 (토큰 0)
- 게임 폴더를 지정하면 MV인지 MZ인지 판별하고 프로젝트를 만든다.
- `data/*.json`, `js/plugins.js`, `js/plugins/*.js` 는 그대로 읽는다.
- 암호화된 이미지(`.rpgmvp`, `.png_`)는 `System.json` 의 키로 푼다. 소리 파일은 건드리지 않는다.
- `package.nw` 로 묶인 게임은 압축을 풀고, Enigma Virtual Box로 뭉친 exe는 내장한 해제 도구(evbunpack)로 푼다.
- 못 푸는 형식이면 이유를 알리고 멈춘다.

### 4.2 텍스트 추출 (토큰 0)
- 이벤트: 대사(화자 이름 포함), 선택지, 스크롤 문장, 이름 변경, 스크립트 호출 속 문자열, 플러그인 커맨드 인자, 주석(플러그인이 읽는 경우).
- 데이터베이스: 액터, 직업, 스킬, 아이템, 무기, 방어구, 적, 상태, 시스템 용어, 게임 제목, 맵 표시 이름, 메모란 태그.
- 플러그인: `plugins.js` 설정값(JSON이 문자열로 겹겹이 들어간 것은 끝까지 풀어서 뽑고, 넣을 때 똑같이 다시 감싼다), 플러그인 JS 파일 속 문자열.
- 연속된 대사 줄은 한 덩어리로 묶는다. 같은 원문은 하나로 합친다. 같은 원문이라도 위치별로 다른 번역을 줄 수 있다.
- 제어문자(`\V[1]`, `\N[2]`, `\C[2]` 등)와 자리 표시(`%1`)는 보호 대상으로 표시한다.
- 일본어 글자가 들어간 문자열만 후보로 삼는다.
- 식별자 의심 표시: 같은 문자열이 다른 곳(스크립트, 플러그인 인자, 메모 태그, 파일 이름)에서 그대로 참조되면 표시를 단다. 표시된 항목은 Claude가 앞뒤 코드를 보고 번역 여부를 판단하며, 판단 전에는 번역하지 않는다.

### 4.3 용어집
세 부분으로 나눈다. (사용자의 기존 지침 문서 구성을 따름)

- **용어 목록**: 원문 = 번역. 상태는 확정 또는 결정 필요. 문맥별로 다른 번역을 둘 수 있다.
- **말투 지침**: 자유 글. 번역 요청마다 그대로 붙인다.
- **형식 규칙**: 프로그램이 검사하는 규칙. 줄 수 일치, 한 줄 최대 길이, 제어문자와 태그 유지, 일본어 글자 남기지 않기 등. 프로젝트마다 켜고 끄고 값을 바꾼다.

애매한 용어 처리 [확정]:
- Claude는 후보 2~3개, 후보별 이유, 추천 하나, 실제 사용 예문을 함께 올린다.
- 사용자가 고르기 전에도 번역은 추천안으로 진행한다.
- 추천안으로 진행된 것은 나중에 한눈에 보이게 표시한다. 용어집에는 "추천안으로 진행 중" 표시와 그 용어가 쓰인 문장 수를 보여주고, 텍스트 화면에서는 그 용어가 들어간 번역문에 표시를 달아 필터로 모아 볼 수 있게 한다. 번역이 끝나면 "결정 안 한 용어 N개"를 알린다.
- 나중에 용어를 바꾸면 프로그램이 그 용어가 들어간 번역문을 전부 찾아 바꾼다. 조사(을/를, 이/가, 은/는, 와/과, 으로/로)는 자동으로 맞추고, 자동으로 못 맞추는 문장만 Claude에게 보낸다.
- 번역 도중 새로 나온 고유명사는 "용어 후보"로 올라온다. [내 선택]

### 4.4 번역 흐름 [확정]
1. **자료 모으기** (프로그램): 인물 이름, 화자 이름, 고유명사 후보, 인물별 대사 표본, 메뉴 용어.
2. **용어집과 말투 지침 초안** (모델 A): 위 자료를 읽고 작성.
3. **사용자 확정**: 용어집 화면에서 읽고 고친다. 확정 전에는 전체 번역이 시작되지 않는다. (결정 필요 항목이 남아 있어도 확정할 수 있다.)
4. **전체 번역** (모델 B): 묶음 단위. 묶음마다 말투 지침, 그 묶음에 나오는 용어, 앞 장면 몇 줄, 형식 규칙을 같이 보낸다. 묶음마다 새 대화로 보낸다.
5. **형식 검사** (프로그램): 어긋난 항목만 번역 모델에게 돌려보낸다. 정해진 횟수를 넘으면 확인 필요로 올린다.
6. **검수** (모델 C): 아래 4.5.

구독 사용량 한도에 걸리면 작업을 멈춰 두었다가 이어서 할 수 있어야 한다. 끝난 묶음은 다시 하지 않는다. [내 선택]

### 4.5 검수 [확정: 버튼 하나로 전체 검수]
- **1단계, 프로그램 검사** (토큰 0): 형식 규칙, 용어집 불일치, 남은 일본어, 제어문자 누락, 같은 원문인데 번역이 다른 것.
- **2단계, Claude 검수**: 원문과 번역을 묶음으로 읽고, 문제 있는 항목만 이유와 고친 안을 달아 확인 필요에 올린다. 전부 다시 쓰지 않는다. 사용자가 항목별로 받거나 거절한다.
- 범위 선택: 전체, 지난 검수 이후 바뀐 것만, 특정 맵만. 시작 전에 예상 토큰을 보여준다.

### 4.6 이미지 [확정: 미리 추출해서 이미지까지 번역]
- 후보 추리기 (토큰 0): `img/pictures`, `img/system`, `img/titles1`, `img/titles2` 등에서 후보를 모아 썸네일 모음판을 만든다. Claude는 모음판을 보고 글자가 있는 이미지를 고른다.
- Claude는 이미지를 보고 작업 지시서를 쓴다: 지울 영역, 넣을 문장, 위치, 폰트, 크기, 색, 정렬.
- 프로그램이 지시서대로 PNG를 찍는다. 지우기는 단색 채우기와 주변 색 채우기를 지원한다.
- 폰트, 크기, 문장을 바꾸면 Claude 없이 바로 다시 찍힌다. 프로젝트 기본 폰트를 바꾸면 전체 이미지에 반영된다. [확정: 폰트 수정 가능]
- 폰트는 이름을 타자로 치지 않고 목록에서 고른다 [확정]. 목록에는 컴퓨터에 설치된 폰트와 프로젝트에 넣어둔 폰트 파일이 나오고, 각 이름이 그 폰트 모양으로 보인다. 검색할 수 있고, 한글이 들어있는 폰트만 보는 필터가 있다. 고르는 즉시 이미지에 반영되어 보인다. 굵기도 목록에서 고른다. 크기와 색은 조절 막대와 색 선택기로 바꾼다.
- 게임 안 글자에 쓰는 폰트(대사창, 메뉴)도 같은 방식으로 고른다. 이 폰트는 파일이 패치 zip에 같이 들어가므로, 배포해도 되는 폰트인지 사용자가 확인하도록 고를 때 안내한다. [내 선택]
- 게임 폰트를 고르면 인게임 미리보기가 바로 바뀐다 [확정]. 폰트 목록에서 항목 위에 올려두기만 해도 대사창, 선택지, 메뉴 미리보기가 그 폰트로 그려진다. 폰트가 바뀌면 글자 폭이 달라지므로 줄 넘침 검사도 다시 계산해서 "이 폰트로 바꾸면 넘치는 줄 N개"를 보여준다.
- 미리보기는 프로그램이 게임 화면을 흉내 내어 그린 것이다. 기본 대사창 기준으로는 실제와 거의 같지만, 대사창을 바꾸는 플러그인을 쓰는 게임은 다를 수 있다. 미리보기 옆에 이 점을 표시하고, 실제 확인은 "게임 실행"으로 한다.
- 배경이 복잡해 깔끔히 지울 수 없는 이미지는 "수작업 필요"로 표시하고, 사용자가 직접 고친 PNG를 넣어 대체할 수 있다. [내 선택]
- 이미지 속 용어도 같은 용어집을 쓴다.
- 빌드 때 원본이 암호화돼 있었으면 같은 키로 다시 암호화한다.

### 4.7 이벤트 보기와 수정
- 이벤트 커맨드를 읽기 쉬운 글로 풀어 보여준다. 예: `스위치 45 [기록1 완료] = 켬`. Claude도 이 형태로 읽는다.
- 역추적 검색: 특정 스위치, 변수, 커먼이벤트, 아이템을 쓰는 곳 전부.
- 수정은 이벤트 페이지 단위의 "바뀐 점"으로 수정 층에 기록한다. 번역표의 위치 정보가 밀리지 않게 처리한다.
- 기능 추가는 되도록 새 플러그인 JS 파일로 넣는다. 기존 JS 수정은 "바뀐 점"으로 기록한다.
- 한글 폰트 적용은 기본 제공 수정으로 둔다(MV, MZ 각각의 방식). [내 선택]
- 수정마다 켜고 끌 수 있고, "원본 버그" 표시를 달 수 있다. 원본 버그만 모아 제작자 전달용 목록으로 뽑는다. [내 선택]

### 4.8 게임 업데이트 [확정]
새 버전 폴더를 가져오면 프로그램이 이전 원본과 비교한다.
- 원문이 그대로인 문장: 기존 번역 자동 적용
- 새로 생기거나 바뀐 문장: "새 문장"으로 모아 번역 대상에 올림. 바뀐 문장은 이전 원문과 이전 번역을 참고로 붙임
- 사라진 문장: 번역은 보관만 함
- 수정 층: 대상 페이지나 파일이 안 바뀌었으면 자동으로 다시 얹음. 바뀌었으면 충돌로 표시하고 Claude에게 넘길 수 있음
- 이미지: 원본 이미지가 바뀐 것만 다시 작업 대상으로 표시. 글자 위치가 같으면 지시서를 그대로 적용

### 4.9 빌드와 패치노트 [확정]
- 결과물: 바뀐 파일만 게임과 같은 경로 구조로 묶은 패치 zip. 패치노트와 설치 방법 파일 포함.
- 빌드 전 검사: JSON이 깨지지 않았는지, 제어문자가 맞는지, 바뀐 파일이 전부 들어갔는지.
- 패치노트: 지난 빌드 이후 바뀐 것을 프로그램이 센다(새 번역 수, 고친 문장, 바뀐 이미지, 수정 내역, 파일 목록). Claude가 읽기 좋은 글로 다듬는다.
- 빌드마다 번호가 붙고 이전 zip과 노트가 남는다.
- "게임 실행": 테스트용 사본을 한 번 만들고, 그 뒤로는 바뀐 파일만 덮어써서 실행한다. [내 선택]

### 4.10 채팅 [확정]
- 프로그램이 Claude CLI를 실행해 대화를 주고받는다. 답과 진행 상황(무엇을 검색하고 읽었는지)을 실시간으로 보여준다.
- 스크린샷을 붙여넣기(Ctrl+V)와 끌어다 놓기로 첨부할 수 있다.
- "이거 번역 안 됐어": Claude가 검색 도구로 위치를 찾고, 원인에 따라 번역표 추가, 수정 내역 기록, 이미지 지시서 추가 중 하나를 한다. 같은 종류가 더 있으면 알려준다.
- Claude는 프로그램이 제공하는 도구만 쓴다. 게임 파일을 직접 읽거나 셸 명령을 쓰지 않는다. [내 선택]
- 채팅에서 Claude가 바꾼 것은 화면에 바로 반영된다. 번역을 고치면 텍스트 화면의 그 줄이, 용어를 바꾸면 용어집이, 이벤트를 고치면 수정 내역이 새로고침 없이 바뀐다. 채팅의 "수정 1건 저장됨" 같은 줄을 누르면 해당 화면의 그 항목으로 이동한다.
- 반대로 사용자가 화면에서 직접 고친 것도 Claude가 다음에 읽을 때 그대로 보인다. 자료는 한 곳에만 있다.
- 채팅에서 한 변경은 되돌릴 수 있다.
- 이번 대화에 쓴 토큰을 보여준다.
- 대화를 새로 시작해도 프로젝트 요약(용어집, 진행 상태, 수정 내역 제목)이 자동으로 붙는다.

Claude에게 주는 도구(초안): 문자열 검색, 문자열 읽기와 번역 쓰기, 용어집 읽기와 쓰기, 이벤트 읽기, 사용처 검색, 수정 기록, 플러그인 코드 조각 읽기, 이미지 모음판 보기, 이미지 보기, 이미지 지시서 쓰기, 확인 필요 목록 읽기와 쓰기, 빌드 상태 읽기.

### 4.11 모델 선택 [확정]

### 4.12 번역되지 않은 항목 처리와 외부 번역용 내보내기 (2026-11-13 추가)

- **거절된 항목을 따로 표시**: 모델이 어떤 항목의 번역을 거절하면 "미번역"과 구분되는 "거절됨" 상태로 표시하고 이유를 함께 남긴다. 말없이 건너뛰거나 엉뚱한 문장으로 채우지 않는다.
- **묶음을 쪼개서 범위 좁히기**: 묶음 전체가 거절되면 프로그램이 더 작은 묶음으로 나눠 다시 보내서, 문제가 된 항목만 남기고 나머지는 번역되게 한다.
- **외부 번역용 내보내기**: 항목을 골라(상태 필터: 미번역, 거절됨, 검토 필요, 또는 직접 선택) 꾸러미 하나로 내보낸다. 사람 번역가나 다른 도구에 넘기는 일반 기능이다. 꾸러미 내용:
  - 항목 JSON: id, 종류, 화자, 원문, 앞뒤 문맥 몇 줄(이미 번역된 줄은 번역도 함께)
  - 그 항목들에 나오는 용어, 말투 지침, 인물 카드, 형식 규칙
  - 돌려받을 형식 설명(`[{id, target}]`)
- **다시 가져오기**: 돌려받은 JSON을 넣으면 같은 형식 검사를 거쳐 번역표에 들어간다. 출처가 외부라는 표시를 남긴다.
- 화면: 텍스트 탭의 상태 필터에 "거절됨"을 추가하고, 필터 결과에 "내보내기"와 "가져오기" 버튼을 둔다.

## 6. 만드는 방식 [내 선택]

- 윈도우용 데스크톱 앱, Electron, TypeScript.
- Claude 연결: Claude CLI를 헤드리스 모드로 실행하고 스트리밍 출력을 읽는다. 프로그램의 기능은 MCP 서버로 제공하고 CLI에 연결한다. 허용 도구를 그 MCP 도구로 제한한다. 모델은 실행 인자로 지정한다. 정확한 옵션 이름은 구현 전에 현재 Claude Code 문서로 확인한다.
- 전체 번역과 검수는 채팅 대화가 아니라 묶음마다 별도 실행으로 돌린다. 결과는 정해진 형식(JSON)으로 받고 프로그램이 검증한다.
- 색과 폰트는 시안을 따른다(어두운 바탕, 청록 포인트). 지금은 이것이 기본 테마 "어두운"이다.

## 9. 실제 게임 시험에서 나온 것 (2026-11-13, MV 게임 1개)

계획 1의 CLI로 실제 MV 배포판 하나를 가져와 추출했다. 항목 6,940개(대사 5,993, 선택지 312, DB 190, 시스템 118, 플러그인 커맨드 225, 플러그인 설정 74, 스크립트 20, 주석 8), 원문 약 23만 자, 경고 0개. 계획 3에서 반영할 것:

- **화자 줄 패턴**: 이 게임은 대사 첫 줄이 `\C[4]【アーテル】\C[0]` 형태의 화자 이름이다. MV에는 화자 칸이 없어서 이런 방식이 흔하다. 프로젝트마다 "화자 줄 패턴"을 정해 첫 줄을 화자로 떼어내고, 이름은 용어집으로 한 번만 번역해 다시 붙인다. 같은 이름을 수천 번 번역하지 않게 된다.
- **플러그인 커맨드 틀**: `addLog <문장>`, `D_TEXT <문장> <크기>`, `ShowInfo …<문장>` 은 뒤쪽이 화면에 보이는 글자이고, `PA_INIT 20 1 連番 1`, `STS 習得回数取得 変数(93) …` 은 전부 식별자다. 커맨드 이름별로 "몇 번째 인자가 표시 글자인지"를 정하는 틀이 필요하다. Claude가 커맨드 이름별로 한 번 판단하면 같은 이름의 나머지에 자동 적용한다.
- **스크립트 속 표시 글자**: `"1_t=2_subject=…回数：\\V[81]"` 처럼 스크립트 문자열 안에 표시 글자가 들어 있다. 문자열 전체가 아니라 그 안의 일본어 구간만 바꿔야 한다.
- **메모란**: 맵 이벤트 39개, 스킬 29개 등의 메모에 일본어가 있다. 용어 사전 플러그인(SceneGlossary)이 메모의 글자를 화면에 보여주므로 추출 대상에 넣어야 한다.
- **변수 조작의 스크립트(코드 122)**: 182곳에 일본어가 있다. 표시 글자인지 확인이 필요하다.
- **건드리면 안 되는 것(추출하지 않는 게 맞음)**: 그림 표시의 파일 이름(코드 231, 약 6,600곳이 일본어 파일 이름), 캐릭터 이미지 이름, 이벤트 이름, 스위치와 변수 이름, 라벨(118, 119).
- **MZ 게임 1개 추가 시험**: 엔진 판별, 추출, 암호화 이미지(`.png_`) 200장 복호화가 모두 정상. 이 게임은 이미 대부분 한국어로 번역된 상태였고, 남은 일본어 605개(대사 276)만 잡혔다. 누군가 하다 만 번역을 이어받는 용도로도 쓸 수 있다.
- **고친 버그**: 가운뎃점 `・`(U+30FB)과 장음 `ー`(U+30FC)가 일본어로 판정되어, 이미 한국어인 대사 277개가 미번역으로 잡혔다. 가나 블록의 문장부호는 일본어 판정에서 뺐다. 형식 검사의 "남은 일본어"에도 같은 판정이 쓰이므로 번역문에 `・・・`이 있어도 오류가 아니다.
- **MZ 플러그인 커맨드(357)**: 인자 값에 `自分の教室に行く`(화면에 보이는 목표 문구)와 `桜月19モザイク`(그림·영상 파일 이름)가 섞여 있다. MV와 같은 틀이 필요하고, MZ는 플러그인 이름 + 커맨드 이름 + 인자 이름으로 구분할 수 있다. 357의 설명 줄(657)과 402의 글자는 편집기용이라 번역하지 않아도 게임에 영향이 없다.

### 사용자가 앱을 써 보고 한 말에서 (2026-11-17, 화면 새단장)

자세한 경과는 `docs/2026-11-17-화면-새단장-설계.md`.

- **겉모양을 일괄로 입히면 "양산형"이 된다.** 모든 화면에 같은 머리·단추·목록 모양을 입혔더니 "단조롭고 다 똑같아서 눈에 안 들어온다, 양산형 프로그램 같다"는 말을 들었다. 장식이나 색다른 콘셉트로는 풀리지 않았고, 화면마다 "여기에 무엇을 하러 오는가"를 먼저 정해 그 일에 필요한 것을 크게, 위에 두고서야 나아졌다.
- **색이 강조색 하나뿐이면 아무것도 눈에 안 들어온다.** 모든 강조가 같은 색이라 상태를 구별할 수 없었다. 끝남·승인(초록), 새로 생김·아직 사람이 안 봄(파랑), 사람이 봐야 함(경고색), 막힘(오류색)을 모든 테마에 두고, 강조색은 주 단추와 지금 고른 것에만 쓴다.
- **긴 지침 글은 통째 입력칸으로는 읽기 어렵다.** 번역 지침을 제목별 묶음으로 나눠 읽는 글로 보여 주고, 고칠 때만 그 묶음을 입력칸으로 바꿨다.
- **좁은 창에서는 오른쪽 패널이 표를 못 쓰게 만든다.** 노트북 폭에서는 가운데 표가 좁아지고 표 위 머리가 화면 높이를 먹었다. 오른쪽 패널을 접게 하고, 창 폭 1440 미만에서는 처음부터 접어 두었다가 서랍으로 겹쳐 연다.
- **붓글씨 같은 장식 글꼴은 일본어·한자 게임 제목을 깨뜨린다.** 장식 글꼴에 없는 글자가 글자마다 다른 글꼴로 떨어졌다. 게임 제목은 일본어·한자가 다 든 글꼴로 고정하고 장식 글꼴은 화면 제목에만 쓴다.
