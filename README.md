# SoSa Translator (MV/MZ 번역 작업실)

RPG Maker MV/MZ 게임을 일본어에서 한국어로 옮기는 윈도우용 프로그램입니다. 게임에서 문장 뽑기, 형식 검사, 번역문 다시 넣기, 패치 zip 만들기 같은 기계적인 일은 프로그램이 하고, Claude 에게는 번역과 판단만 맡깁니다. Claude 가 게임 전체를 읽지 않고 프로그램이 추린 조각만 보므로 토큰을 아낍니다.

- **원본 게임 폴더에는 아무것도 쓰지 않습니다.** 모든 작업 결과는 프로젝트 폴더에 쌓이고, 빌드하면 바뀐 파일만 묶은 패치 zip 이 나옵니다.
- 데스크톱 앱(Electron), 그 밑의 라이브러리(`src/core`), 명령줄 도구(`src/cli.ts`)로 되어 있습니다.
- 만든 까닭과 정한 것: `docs/2026-11-13-mvmz-번역작업실-기획서.md`. 코드 구조: `docs/ARCHITECTURE.md`.

## 준비물

- **Windows 10/11**
- **Claude CLI 와 로그인**: 채팅, 자동 번역, 검수, 판단 추천, 패치노트 다듬기는 Claude CLI(`claude`)와 본인의 Claude 구독으로 동작합니다. 터미널에서 설치하고 한 번 로그인합니다.

  ```bash
  winget install Anthropic.ClaudeCode
  ```

  ```bash
  claude
  ```

  앱은 PATH 에서 `claude.exe`(없으면 `claude.cmd`)를 찾고, 설정 화면의 "Claude CLI" 에서 경로를 직접 줄 수도 있습니다. CLI 가 없어도 가져오기, 손 번역, 빌드는 됩니다. 이때 채팅 탭에 설치와 로그인 안내가, 아래 상태 줄에 "Claude CLI 없음" 또는 "로그인 필요"가 보입니다(로그인 여부는 `claude auth status` 로 확인하고, 5초 안에 답이 없으면 모름으로 칩니다).
- **소스에서 실행할 때만**: Node 22.12 이상(64비트)과 git.

## 실행

설치 파일(`release/` 의 `SoSa Translator Setup …exe`)이나 zip 을 받았다면 그대로 실행합니다. 소스에서 실행하려면:

```bash
npm install
```

```bash
npx install-electron
```

```bash
npm run dev
```

`npx install-electron` 은 Electron 실행 파일을 받는 것으로, 처음 한 번만 합니다.

앱 설정(`settings.json`, 폰트 목록 캐시 `fonts-cache.json`, 채팅용 Claude CLI 가 읽는 `mcp.json`)은 윈도우의 앱 설정 폴더(`%APPDATA%` 아래)에, 프로젝트는 기본으로 `문서/MVMZ 번역 작업실/<이름>` 에 만들어집니다. 프로젝트 폴더 위치는 설정에서 바꿀 수 있습니다.

화면 색은 설정 → 테마에서 고릅니다. 견본 카드 여덟 가지(어두운, 밝은, 붉은 달밤, 촛불 어둠, 먹빛 강호, 심우주 청록, 고전 RPG 파랑, 한지와 먹) 가운데 하나를 누르면 바로 바뀝니다. 창 틀은 앱이 직접 그리므로 맨 위 띠를 끌어 창을 옮기고, 두 번 누르면 최대화됩니다. **Ctrl+K**(또는 타이틀바 가운데의 검색 단추)를 누르면 명령 검색창이 열립니다. 왼쪽 메뉴의 화면으로 가기, 패치 빌드·게임 실행·새 버전 가져오기·프로젝트 닫기·미번역 줄 번역하기·번역 전체 검수, 표 거르기(미번역, 검토 필요, 오류, 창 넘침)를 한글이나 초성(예: `ㅇㅇㅈ` → 용어집)으로 거르고, 위아래 화살표와 Enter 로 고릅니다. 친 글자는 "문장 찾기"로 텍스트 화면의 찾기 칸에 넣을 수 있습니다. 지금 할 수 없는 것은 흐리게 이유와 함께 보입니다. Esc 나 바깥을 누르면 닫힙니다. 번역·검수·용어집 초안이 끝났을 때, 되돌렸을 때, 외부 번역을 가져오거나 내보냈을 때는 창 오른쪽 아래에 3초 동안 알림이 뜹니다(오류는 알림이 아니라 그 자리에 남습니다). 진행·승인·가져오기 같은 순간의 짧은 움직임이 거슬리면 설정 → 움직임에서 "움직임 켜기"를 끕니다(윈도우에서 애니메이션 효과를 꺼 두었으면 처음부터 멈춰 있습니다).

## 처음부터 끝까지 한 번 해 보기

### 1. 가져오기

첫 화면에서 "게임 폴더 고르기"를 누르거나 게임 폴더(또는 그 안의 파일)를 끌어다 놓습니다. 엔진(MV/MZ)과 제목을 확인하고 프로젝트 이름을 정해 "만들기"를 누르면, 게임의 `data/*.json`, `js/plugins.js`, `js/plugins/*.js` 를 프로젝트의 `original/v1/` 로 복사하고 번역할 문장을 모두 뽑습니다. 같은 종류·같은 화자·같은 원문은 하나로 합쳐 한 번만 번역합니다. 

exe 하나로 뭉쳐진 게임(Enigma Virtual Box)은 그 폴더나 exe 를 놓으면 "풀고 계속" 버튼이 나옵니다. 누르면 프로젝트 폴더 안의 `_풀린 게임/<폴더 이름>/` 에 게임 파일을 풀고 그 폴더로 이어서 진행합니다. 원본 exe 는 읽기만 합니다. 풀린 폴더에는 게임 파일만 있고 실행 파일은 들어 있지 않으므로, 번역한 게임을 돌리려면 같은 엔진(MV/MZ)의 다른 게임에서 실행 파일들(Game.exe 와 그 옆의 dll 등)을 가져다 놓아야 합니다. 패치 zip 도 원본 exe 가 아니라 이 풀린 폴더에 덮어씁니다.

왼쪽 메뉴: 텍스트 · 용어집 · 설정 · 판단 필요 · 이벤트 · 수정 내역 · 이미지 · 빌드 기록 · 작업 기록 (게임 업데이트를 가져온 뒤에는 업데이트 결과). 위 막대: 프로젝트 닫기 · 새 버전 가져오기 · 게임 실행 · 패치 빌드.

### 2. 용어집

"용어집"에서 "용어집 초안 받기"를 누르고 방식을 고릅니다.

- **적당히 읽기**(기본): 대본에서 고르게 떨어진 장면(약 2,500자씩, 읽는 양 2만/5만/10만 자)과 주요 인물·신음 장면을 골라 읽습니다.
- **전체 정독**: 대사 전부를 약 2만 자 조각으로 읽습니다.
- **표본만**: 화자 이름, 고유명사·효과음 후보, 인물별 대사 표본, 메뉴 용어만 모아 한 번 보냅니다.

읽는 방식은 조각마다 CLI 를 한 번씩 불러 인물 성격·말투·신음의 결, 고유명사, 효과음을 메모하고(`draft-notes.json`, 같은 조각은 다시 읽지 않음), 모은 메모를 한 번 더 보내 정리합니다. 시작 전에 조각 수와 예상 입력 토큰이 보입니다. 답은 용어(애매하면 후보 2~3개), 인물 카드, 이 게임의 말투로 돌아와 용어집에 합쳐지고, 이미 있는 용어와 인물은 건드리지 않습니다. 화자 줄 패턴이 비어 있으면 자동으로 찾아 넣습니다.

용어집 화면에서 용어(이름·장소·용어·효과음·기타), 인물 카드(말투, 1인칭, 호칭, 신음 스타일), 형식 규칙(제어문자 유지, 일본어 남기지 않기, 줄 수, 문장부호·숫자·영문을 반각으로, 괄호 （ ）도 반각으로, 표기 검사, 가린 글자는 풀어서 쓰기, 창을 넘는 줄은 자동으로 나누기, 최대 줄 수, 한 줄 최대 글자 수, 화자 줄 패턴)을 고친 뒤 **"용어집 확정"**을 누릅니다. 확정해야 전체 번역을 맡길 수 있고, 결정 안 한 용어가 남아 있어도 확정할 수 있습니다. 후보 중 추천안으로 진행 중인 용어가 들어간 번역문은 "추천안 용어 사용"으로 표시됩니다.

분류가 이름인 용어에는 **"화자만"** 체크가 있습니다. 【先生】처럼 화자 이름으로 등록했지만 다른 인물이 호칭으로도 쓰는 말에 켭니다. 켜면 그 번역은 화자 이름 자리(화자 줄, 이름 칸)에만 맞추고, 대사 안의 호칭은 인물 카드의 "호칭"을 따릅니다. 용어 번역을 바꿀 때도 화자 이름 자리의 번역문만 따라 바뀝니다. 호칭과 말투는 언제나 인물 카드가 용어집보다 우선합니다.

같은 자리의 **"이름으로 쓰일 때만"** 체크는 인물 이름이 보통 낱말과 글자가 같을 때(이름 ハナ 와 꽃 花 처럼 읽히는 말) 켭니다. 그 용어는 번역·검수·내보내기에 "이름으로 쓰인 곳에만 적용"이라는 표시와 함께 보내져, 보통 낱말로 쓰인 곳은 문맥대로 옮기고 검수도 그곳을 "용어집과 다름"으로 짚지 않습니다. 프로그램은 문장 안에서 이름과 낱말을 가릴 수 없어 본문은 검사하지 않고, 화자 줄과 이름 칸에서만 맞는지 봅니다. 용어 번역을 바꾸면 범위가 없는 용어처럼 그 번역이 쓰인 곳이 모두 바뀝니다. 두 체크는 하나만 켜집니다. 용어에 적어 둔 메모(note)도 번역·검수·내보내기에 함께 보냅니다.

용어의 번역을 바꾸면 그 용어가 들어간 번역문을 모두 찾아 바꾸고, 뒤의 조사(을/를, 이/가, 은/는, 과/와, 으로/로, 아/야, 이랑/랑, 이나/나, 이라/라, 이야/야)를 받침에 맞춥니다. 조사인지 확실하지 않은 문장은 바꾸되 "검토 필요"로 올립니다.

**번역 지침**: 왼쪽 메뉴의 "번역 지침" 화면에는 실제로 전달되는 글 전체가 그대로 보입니다. "전체 번역", "검수", "내보내기" 탭마다 글이 따로 있고, 보이는 글을 고치면 고친 그대로 전달됩니다(프로그램이 뒤에서 더 붙이는 문구는 없습니다).

- `<번역 지침>` 과 `</번역 지침>` 사이가 지침 본문입니다. 세 탭과 채팅, 용어집 초안이 같이 쓰므로 어느 탭에서 고쳐도 모두 바뀝니다. 새 프로젝트의 처음 값은 `docs/default-style-guide.md` 입니다(앱을 빌드할 때 그대로 들어갑니다).
- 그 밖의 글(형식 규칙, 입력·출력 설명, 돌려줄 형식)은 그 탭에만 적용됩니다. "형식 규칙:" 아래 줄들은 손대지 않으면 용어집 화면의 형식 규칙 값을 따라 바뀌고, 고치면 고친 대로 굳습니다.
- 입력·출력을 설명하는 부분을 크게 바꾸면 답을 읽지 못할 수 있습니다. "처음 문구로 되돌리기"로 그 탭의 글을, "지침 본문을 기본 지침으로"로 본문을 되돌립니다.

### 3. 번역

"텍스트" 화면의 "새 문장 n개 번역 맡기기"를 누르면 판단 필요가 아닌 미번역 문장을 파일별로 최대 40개, 본문 6,000자씩 묶어 묶음마다 CLI 를 한 번씩 부릅니다. 묶음에는 번역 지침 화면의 "전체 번역" 글, 그 묶음에 나오는 용어와 인물 카드, 바로 앞 대사 3줄이 붙습니다. 화자 줄은 떼고 본문만 보내고, 이름은 용어집대로 옮겨 다시 붙입니다. 돌아온 번역의 전각 문장부호·숫자·영문은 반각으로 맞춥니다(괄호는 원문 그대로).

- 형식 오류가 난 문장만 한 번 더 보냅니다. 모델이 거절한 문장은 "거절됨"으로 남습니다. 묶음 전체가 거절되거나 답 형식이 틀리면 반으로 나눠 다시 보냅니다.
- 사용량 한도에 걸리면 "사용량 한도 때문에 멈췄어요"가 되고 "이어하기"로 그 묶음부터 다시 합니다. 끝난 묶음은 번역표에 남으므로 앱을 다시 켜도 남은 것만 보냅니다.
- 문장을 고르면 오른쪽 "항목" 탭에서 손으로 고치거나, 승인하거나, "다시 번역"하거나, "채팅으로 말하기"로 채팅에 붙일 수 있습니다. "채팅" 탭에서는 Claude 와 이야기하며 고칩니다(아래 채팅 도구 참고).
- 항목 탭의 번역 칸 아래 "비슷한 번역"에는 전에 번역한 비슷한 문장이 일치율과 함께 나옵니다(프로그램이 계산하므로 토큰을 쓰지 않습니다). 같은 자리의 **"Claude 초안 받기"**를 누르면 그 한 줄만 Claude 에게 번역시켜 목록에 "Claude 초안"으로 보여 줍니다. 전체 번역이 그 줄 하나에 싣는 것(번역 지침, 그 줄의 용어와 인물 카드, 앞 대사 3줄)만 보내고 CLI 를 한 번 부르므로 **토큰을 씁니다**. 줄을 고를 때 저절로 받지 않고, 쓴 토큰은 아래 상태 막대의 사용량에 더해집니다. 번역표에는 쓰지 않으며, "가져오기"는 번역 칸만 바꾸니 읽어 보고 직접 저장합니다. 다른 줄을 고르면 사라집니다. 용어집을 확정하기 전이나 다른 작업이 도는 동안에는 누를 수 없습니다.
- "표 | 스토리"로 바꾸면 고른 범위의 장면(이벤트 페이지, 커먼이벤트, 전투 이벤트 페이지)을 순서대로 읽을 수 있고, 장면마다 "이 장면 다시 번역"과 "장면 승인"이 있습니다.

**번역 상태**

| 상태 | 뜻 |
|---|---|
| 미번역 `untranslated` | 번역 없음 |
| 번역 완료 `translated` | 번역 있음 (기본). 패치에 들어갑니다 |
| 검토 필요 `needs-review` | 사람이 볼 것: 검수가 문제를 짚음, 업데이트 때 이전 번역을 미리 넣음, 용어를 바꾸며 조사가 불확실함, 직접 올림 |
| 승인 `approved` | 사람이 확인함 |
| 오류 `error` | 형식 검사 오류. 패치에서 빠집니다 |
| 거절됨 `declined` | 모델이 번역을 거절함. 이유가 함께 남습니다 |

**외부 번역**: 텍스트 화면의 "내보내기"는 지금 표에 보이는 문장을 꾸러미 파일(`mvmz-exchange-1`: 번역 지침 화면의 "내보내기" 글, 나오는 용어와 인물, 문장마다 본문·화자·그대로 둘 조각·앞뒤 대사)로 저장합니다. 돌려받은 `[{ "id", "target" }]` 를 "외부 번역 가져오기"하면 넣을 수 있는 수, 검사 오류, 이미 다른 번역이 있어 충돌하는 수(기본은 건너뛰기), 없는 id, 모양이 틀린 항목을 먼저 보여 준 뒤 넣습니다. 들어간 번역은 "외부 번역"으로 표시됩니다.

**게임 제목**: 위 막대의 연필 버튼으로 번역 제목을 정하면 패치에 `index.html` 의 `<title>` 과 최상위 `package.json` 의 `window.title`(비어 있지 않을 때만)이 들어갑니다.

### 4. 검수

텍스트 화면의 "번역 전체 검수"에서 범위(전체, 지난 검수 이후 바뀐 것만, 지금 보는 범위)를 고르면 문장 수와 예상 입력 토큰이 보입니다. 문제가 있는 줄에만 이유와 고친 안이 붙어 "검토 필요"로 올라오고, 나머지는 "번역 완료"로 남습니다. 항목 탭에서 "고친 안 받기" 또는 "그대로 두기"를 고르면 그 줄도 번역 완료로 돌아갑니다. 고른 뒤에도 의견은 "지난 검수 의견"으로 그 항목에 남아서, 고치기 전 번역과 고친 안을 다시 보고 반대쪽으로 바꿀 수 있습니다(잘못 눌렀거나 게임에서 보니 어색할 때). 의견마다 종류(오역·누락, 말투·호칭, 용어, 의성어·신음, 표기, 어색함)가 붙어서, "검토 필요"를 고르면 그 아래 종류별 칩으로 한 종류만 모아 볼 수 있습니다. 같은 종류의 의견이 많으면 종류 칩이나 지적 내용 검색(예: 괄호, 전각)으로 모은 뒤 목록 위의 "모두 고친 안 받기"나 "모두 그대로 두기"로 한 번에 처리합니다. 목록의 "검수로 바뀜", "검수 의견 넘김"으로 그런 문장만 모아 보고, 그 상태로 내보내면 파일에 검수 이유(review)가 함께 들어갑니다. "그대로 두기"로 넘긴 의견이 달린 줄은 그 뒤 번역을 고치지 않았으면 다음 검수에 다시 보내지 않아서, 같은 의견이 또 오지 않고 토큰도 아낍니다(검수 창의 "넘긴 의견이 달린 줄은 다시 검수하지 않기"를 끄면 다시 보냅니다).

**표기 검사**: 번역 지침 가운데 프로그램이 볼 수 있는 표기는 검수를 맡기지 않아도 프로그램이 번역을 쓸 때마다 확인합니다(토큰이 들지 않습니다). 낱말 뒤에 붙은 "읏"(있어읏, 안 돼읏), 번역에 남은 가림 기호(お○んこ → 보○), 말줄임표 길이(… 하나는 ……), ♥ ♪ ? ! ~ 의 개수가 원문과 다른 것, "괄호 （ ）도 반각으로"가 켜져 있는데 남은 전각 괄호를 "주의 · 표기"로 알립니다. 경고일 뿐이라 상태는 바뀌지 않고 빌드에도 들어갑니다. 지침이 바뀌기 전에 번역한 줄도 다시 확인하므로 목록의 "표기 경고"로 모아 볼 수 있습니다. 용어집 화면의 형식 규칙 "표기 검사"로 끄고, "가린 글자는 풀어서 쓰기"를 끄면 가림 기호만 보지 않습니다(○○さん, ××年 처럼 일부러 감춘 것은 원래 보지 않습니다).

### 5. 판단 필요

플러그인 커맨드(356/357), 스크립트(355/655), 주석(108/408), 플러그인 설정, 메모란(`<태그:값>`, `<태그>…</태그>`, `<태그 조건>…</태그>`), 켜진 플러그인의 JS 파일 안 문자열에는 화면에 보이는 글자와 **코드가 읽는 값**이 섞여 있습니다. 코드가 읽는 값을 번역하면 게임이 깨지므로, 이것들은 따로 "판단 필요"로 두고 정한 뒤에만 번역합니다. 비슷한 것끼리 "판단 키"로 묶어 한 번만 정합니다.

| 종류 | 판단 키 |
|---|---|
| MV 플러그인 커맨드 | `mv:<첫 조각>` |
| MZ 플러그인 커맨드 인자 | `mz:<플러그인>:<커맨드>:<인자>` |
| 플러그인 설정값 | `param:<플러그인>:<경로>` (배열 번호는 `[*]`) |
| 플러그인 설정 안 객체의 열쇠 이름 | `param-keys:<플러그인>:<객체까지의 경로>` |
| 스크립트, 주석 | `shape:<모양>` (일본어 구간은 `◆`, 숫자는 `#`) |
| 메모란 태그 | `note:<파일 종류>:<태그>`(`<profile Switch: 704>` 같은 조건 붙은 블록도 이름만: `note:Actors:profile`) |
| 플러그인 JS 문자열 | `js:<파일 이름>` 묶음, 또는 문자열마다 `unit:<id>` |

1. "판단 필요" 화면에서 "Claude에게 추천 받기": 플러그인 주석(`@type file` 같은 것)과 그림·소리 파일 이름으로 확실한 것은 호출 없이 정하고, 남은 묶음을 30개씩(JS 문자열은 앞뒤 60자 문맥과 함께 40개씩) 보냅니다. 결과는 "추천"으로 남습니다.
2. "추천 전부 받아들이기", 또는 카드마다 "번역함"(어디를 번역할지 고르기)/"번역 안 함"으로 확정합니다. 확정된 결정만 번역 대상이 되고, 결정이 없는 문장은 번역도 패치도 하지 않습니다. "그대로 둘 부분"은 `whole`(값 전체가 글자), `args`(MV 커맨드의 앞 `from`개·뒤 `dropLast`개 조각은 그대로), `spans`(일본어 구간만 번역) 중 하나입니다. `unit:<id>` 결정이 묶음 결정보다 우선합니다.
3. 번역할 때 그대로 둘 조각을 함께 보내고, **뼈대 검사**가 그 조각이 한 글자도 바뀌지 않고 순서대로 남았는지 확인합니다. 어긋나면 한 번 다시 보내고, 또 어긋나면 오류로 두어 패치에서 뺍니다.
4. 빌드할 때 메모란은 그 태그의 값만, 플러그인 JS 는 따옴표 안쪽만 바꿉니다(파일의 나머지는 그대로). 추출 뒤에 JS 파일이 바뀌어 자리가 맞지 않으면 그 파일은 넣지 않고 경고합니다.

결정을 "번역 안 함"으로 되돌려도 번역문은 번역표에 남고 패치에서만 빠집니다.

플러그인 설정값이 JSON 객체이고 화면에 보이는 글자가 값이 아니라 **열쇠 이름**인 경우가 있습니다(예: 옵션의 메시지 속도 목록 `{"最遅": -2, "標準": 0, …}`). 이런 일본어 열쇠 이름도 항목으로 뽑아 `param-keys:` 묶음으로 따로 판단합니다(위치 이름 "플러그인 설정 · 열쇠 이름"). 같은 글자의 대사나 값을 번역해도 열쇠 이름은 따로입니다. 열쇠 묶음과 아래의 영어 항목 묶음은 추천을 받을 때 그 설정을 읽는 플러그인 코드 몇 줄(최대 800자)을 함께 보내, 코드가 그 이름을 화면에 찍기만 하는지 이름으로 찾는지 보고 정하게 합니다. 자동 추천은 열쇠 묶음을 정하지 않습니다. 빌드할 때는 그 객체의 순서와 값을 지키고 이름만 바꾸며, 바꾼 이름이 같은 객체의 다른 열쇠와 겹치면 그 열쇠는 바꾸지 않고 경고합니다.

일본어가 없는 글자(예: 옵션 이름 `Monitor FPS Sync`)는 뽑지 않습니다. 이런 글자를 번역하려면 채팅에서 "`Monitor FPS Sync` 를 번역 항목에 넣어 줘"처럼 부탁합니다(`add_extract_text`). 플러그인 설정의 값이나 열쇠 이름과 글자 전체가 같을 때만 `extract.json` 에 적고 바로 다시 뽑아 판단 필요 항목이 생깁니다.

### 6. 이미지

"이미지"에서 게임 그림 속 글자를 번역합니다. 그림 파일을 직접 고치지 않고 **작업 지시서**(지울 영역, 넣을 문장, 폰트, 크기, 색, 정렬, 테두리, 그림자)를 저장하면, 프로그램이 지시서대로 그림을 찍어 패치에 넣습니다. 폰트나 문장을 바꾸면 Claude 없이 다시 찍힙니다.

- 대상 폴더: 기본은 `img/pictures`, `img/titles1`, `img/titles2`, `img/system`, `img/parallaxes`(하위 폴더 포함, `.png`·`.png_`·`.rpgmvp`). 설정의 "이미지"에서 바꿉니다.
- 그리기: 화면에 보이지 않는 창의 캔버스로 찍습니다. 원본 → 영역마다 지우기(색으로 채움, 또는 영역 바로 바깥 색의 평균으로 채움) → 글(그림자 → 테두리 → 채우기). 문장이 영역 폭을 넘으면 공백에서(없으면 글자 단위로) 줄을 바꾸고, 닫는 문장부호는 줄 맨 앞에 오지 않게 합니다. 높이를 넘치면 넘친 채로 찍고 "영역을 넘쳐요"로 알립니다(글자를 몰래 줄이지 않음).
- 패치에는 "끝남"이고 문제가 없는 그림과 "직접 고침"으로 넣은 PNG 만 들어갑니다. 원본이 암호화 파일이면 같은 키로 다시 암호화해 같은 경로에 넣습니다.
- 원본 내보내기: 그림을 고른 뒤 "원본 내보내기"를 누르면 그 그림을, 왼쪽의 "보이는 원본 n장 내보내기"를 누르면 지금 필터와 폴더로 거른 그림 전부를 고른 폴더에 꺼냅니다. 암호화된 그림(`.png_`, `.rpgmvp`)도 풀린 `.png` 로 나오고, `img/pictures/…` 같은 폴더 구조는 그대로 둡니다. 게임 폴더와 그 안으로는 내보내지 않습니다. "직접 고친 그림 넣기"의 짝입니다: 내보낸 PNG 를 그림 도구에서 **같은 크기로** 고친 뒤 그 버튼으로 다시 넣습니다.
- 문제 표시: 지시서를 쓴 뒤 원본 그림이 바뀌면 "원본이 바뀜"(확인 전에는 패치에서 빠짐), 폰트 파일이 없으면 "폰트 없음". 찍기에 실패하면 그 그림만 실패로 남고 빌드는 계속됩니다.
- 채팅에 그림을 붙여 맡길 수도 있습니다. Claude 는 모음판(번호 붙은 썸네일 20장)으로 글자가 있는 그림을 고르고, 크게 본 뒤 지시서를 냅니다. 그림은 긴 변 1,568px 을 넘지 않게 줄여 보냅니다.

### 7. 이벤트 수정

"이벤트"에서 파일(맵, 커먼이벤트, 전투 이벤트)과 이벤트(맵은 페이지마다)를 고르면 커맨드를 한국어 한 줄씩 풀어 보여 줍니다. 줄 번호는 원본 목록의 번호입니다. 스위치·변수·커먼이벤트 이름을 누르면 오른쪽에 사용처(켬/조건)가 뜹니다. 줄을 지우거나 끼워 넣어 "수정으로 기록"하거나, "채팅으로 말하기"로 Claude 에게 맡깁니다.

수정은 원본을 고치지 않고 `patches.json` 에 "원본 대비 바뀐 점"으로 쌓이고, "수정 내역"에서 켜고 끄거나 지웁니다.

| 수정 종류 | 하는 일 |
|---|---|
| `event` | 이벤트 목록 하나에 대한 연산: `insert after`(-1 이면 맨 앞), `delete at`, `replace at`. 번호는 모두 원본 번호. 한 목록에 켜진 수정은 하나 |
| `json` | 데이터 파일의 값 하나 |
| `plugin` | 새 플러그인 파일 `js/plugins/<이름>.js` 와 `js/plugins.js` 끝의 등록 |
| `font` | 게임 폰트 넣기(아래 8) |
| `josa` | 조사 자동 맞춤(아래) |

**조사 자동 맞춤**: "수정 내역" 맨 위의 스위치를 켜면 작은 플러그인 `js/plugins/MVMZ_KoreanJosa.js` 가 패치에 들어가고 `js/plugins.js` 맨 끝(다른 플러그인 수정보다도 뒤)에 등록됩니다. 게임이 `%1`(시스템 문구)이나 `\N[n]`·`\V[n]`·`\P[n]`(대사)에 이름·숫자를 넣은 뒤, 바로 뒤의 `은(는)`·`이(가)`·`을(를)`·`과(와)`·`아(야)`(양쪽 순서 모두)와 `(으)로`·`(이)라`·`(이)나`·`(이)랑`·`(이)야`·`(이)여`·`(이)고`·`(이)다`·`(이)든`·`(이)면` 을 앞 글자에 맞춰 하나로 고릅니다. 그래서 `%1은(는) 싸움에서 패배했다.` 처럼 번역해 두면 게임에서 "티아루시는 싸움에서 패배했다."로 나옵니다. 색 코드와 닫는 괄호·따옴표는 건너뛰고, 본 글자가 한글이면 받침, 숫자면 읽는 소리, 영문이면 끝 글자로 정합니다. 가나·한자처럼 정할 수 없으면 그대로 둡니다. 플러그인 파일은 앱에 묶여 있어 앱을 올리면 다음 빌드에 새 것이 들어갑니다. 같은 이름의 파일이 게임에 있으면 충돌입니다. 게임의 켜진 플러그인 중 `String.prototype.format` 이나 `Window_Base.prototype.convertEscapeCharacters` 를 원래 것을 부르지 않고 통째로 바꾸는 것이 있으면(코드 글자로 어림) 스위치 아래에 그 이름을 알립니다.

빌드할 때 원본 커맨드마다 원래 번호 꼬리표를 붙이고, 수정을 원본 번호로 적용한 뒤, 번역을 꼬리표로 찾아 넣습니다. 그래서 수정으로 줄이 밀려도 번역이 제자리에 들어가고, 번역이 걸린 커맨드를 지운 수정이면 그 번역만 건너뜁니다. 원본이 수정을 기록했을 때와 달라졌으면(내용 기준 해시, 공백·키 순서는 무시) 그 수정은 넣지 않고 "충돌"로 표시합니다.

"원본 버그"로 표시한 수정은 "제작자 전달용 목록"에서 마크다운으로 모아 볼 수 있습니다(제목, 위치, 무엇을 왜, 풀어쓴 연산).

### 8. 미리보기와 폰트

설정의 "게임 폰트"에서 폰트를 고르면(목록에 마우스를 올리면 그 폰트로 넘치는 줄 수를 미리 셉니다) 항목 탭에 "게임 화면 미리보기"가 나오고, 대사의 줄 폭 검사가 글자 수 대신 실제 픽셀 폭으로 바뀝니다(경고라서 패치에는 들어갑니다). 폰트를 정하지 않았거나 파일이 없어지면 글자 수 검사로 돌아갑니다.

- **크게 보며 고치기**: 게임 화면 미리보기의 이 단추를 누르면 가운데 텍스트 표 위에 대사창이 크게 펼쳐집니다. 그 아래 입력칸은 항목 탭의 번역 칸과 같은 글이라 어느 쪽에 써도 되고, Ctrl+Enter 로 저장합니다. 맞춤 표시("1줄 / 최대 4줄 · 폭 29%", 넘치면 붉은 글자)를 보며 "이전 줄"·"다음 줄"로 지금 목록의 대사만 차례로 넘깁니다. "작게"나 채팅 탭으로 가면 접힙니다.
- 폰트 목록: 윈도우 글꼴 폴더 두 곳, 게임의 `fonts/`, 프로젝트의 `fonts/`, 직접 고른 파일. `.ttf`·`.otf` 만 쓰고 `.ttc`(모음 파일)는 수만 보여 줍니다. "한글 있는 폰트"는 가·힣·뷁 세 글자가 모두 있는 폰트입니다.
- 대사창 치수: MV 816(여백 18, 글 여백 6, 글자 28, 줄 36, 4줄, 얼굴 168), MZ 808(12, 8, 26, 36, 4줄, 얼굴 164)에서 시작해, MZ 는 `System.json` 의 `advanced.uiAreaWidth`·`fontSize`, MV 는 켜진 `Community_Basic`(`screenWidth`), `YEP_CoreEngine`(`Screen Width`, `Font Size`, `Window Padding`, `Text Padding`, `Face Width`, `Line Height`, `Icon Width`), `YEP_MessageCore`(`Default Width`, `Default Rows`, `Font Size`, `Face Indent`)를 불러오는 순서대로 반영합니다(나중 플러그인이 이김). 그 밖의 플러그인이 창을 바꾸는 게임은 "대사창 치수 고치기"나 아래 "창 크기와 줄바꿈"에서 손으로 맞춥니다.
- 창 종류: 대사는 **대사창**, 아이템·무기·방어구·스킬 설명은 **설명창**(화면 폭, 2줄)에서 잽니다. MV 대사창의 글 폭은 엔진처럼 창 폭에서 여백만 뺀 값(기본 780px, 얼굴 그림이 있으면 168px 더 좁음), 설명창은 거기서 글 여백을 한쪽만 더 뺀 값입니다. 이름, 선택지, 전투 문구, 프로필, 플러그인 설정은 재지 않습니다. 한 문장이 다른 자리(예: 이름)에도 쓰이면 재기만 하고 자동으로 고치지는 않습니다. 경고는 "2번째 줄이 대사창을 67px 넘어요", "설명창은 2줄인데 3줄이에요"처럼 어느 창인지 알려 주고, 목록의 **"창 넘침"**으로 모아 볼 수 있습니다.
- **창 크기와 줄바꿈**(설정): 창마다 "한 줄 너비(px)"와 "줄 수"를 고칩니다. 비워 두면 게임에서 읽은 값(흐린 글자)을 쓰고, 옆에 게임 폰트로 잰 "한글 약 n자"가 보입니다. **"줄바꿈 다시 맞추기"**는 고칠 줄 수를 먼저 묻고, 창을 넘는 번역의 줄바꿈 자리만 옮깁니다: 빈칸에서만 나누고 쉼표·마침표·말줄임표·물음표·느낌표·닫는 괄호 뒤를 먼저 고르며, 제어문자와 화자 줄은 끊지 않고, 마지막 줄에 두세 글자만 남기지 않습니다. 나눠서 줄 수가 넘치면 글 전체를 다시 흘려 넣어 보고, 그래도 안 되거나 빈칸이 없거나 검사에 새 문제가 생기면 그대로 둡니다(그런 줄은 "창 넘침"에 남으니 문장을 줄여 고칩니다). 작업 기록에 "줄바꿈 다시 맞추기 n줄" 하나로 남아 한 번에 취소할 수 있고, 상태와 검수 기록은 바뀌지 않습니다. "창 넘침" 필터에서는 목록 위의 같은 버튼이 보이는 줄만 고칩니다. 형식 규칙 "창을 넘는 줄은 자동으로 나누기"(기본 켬)가 켜져 있으면 번역 작업, 검수 고친 안, 채팅, 외부 번역 가져오기로 들어오는 번역도 저장할 때 같은 방식으로 맞춥니다(항목 탭에서 직접 친 번역은 그대로).
- 배치: `\C[n]` 색, `\V[n]`(값을 모르면 123), `\N[n]`·`\P[n]`(액터 이름, 번역이 있으면 번역), `\G`, `\I[n]`(아이콘), `\{`·`\}`(글자 크기)를 게임처럼 풉니다. `\n<이름>` 같은 이름 칸 코드는 폭을 차지하지 않습니다. 폰트에 없는 글자는 "이 폰트에 없는 글자 n개"로 알립니다. 얼굴 그림이 있는 대사는 그만큼 좁게 잽니다. 글자 색은 게임의 `img/system/Window.png` 에서 읽습니다.
- **폰트를 게임에 넣기**: 설정에서 켜면 고른 폰트가 패치에 들어갑니다(MZ 는 `fonts/mvmz-game-font.ttf`(또는 `.otf`)와 `System.json` 의 `advanced.mainFontFilename`, MV 는 폰트와 `fonts/gamefont.css`). "쓰는 글자만 남겨 용량 줄이기"를 켜면 번역문, 수정으로 넣은 글, 숫자·영문·문장부호·전각 기호만 남깁니다. 지난 빌드의 폰트 크기와 "이 폰트에 없는 글자 n개"가 함께 보입니다. 배포해도 되는 폰트인지는 직접 확인하세요.

### 9. 빌드와 게임 실행

위 막대의 **"패치 빌드"**는 형식 검사 뒤 원본과 달라진 파일만 묶어 `builds/NNN/` 에 패치 zip 을 만듭니다. 오류인 번역은 빠지고 그 수가 표시됩니다. zip 최상위에는 `패치노트.txt`(이번 빌드의 글 다음에 지난 빌드들의 글을 최신순으로)와 `설치 방법.txt` 가 들어갑니다.

"빌드 기록"에서 빌드마다 패치노트를 고쳐 저장하거나 "Claude에게 다듬기 맡기기"를 누르면 그 빌드의 zip 안 글도 바뀝니다.

**작업 기록**: 왼쪽 메뉴의 "작업 기록"에는 번역문에 생긴 변화가 행동마다 최신순으로 남습니다(언제, 누가: 사용자·번역 작업·검수·채팅·외부 번역, 무엇을, 바뀐 줄 수). 직접 고침, 상태 바꿈, 지우기, 검수 의견 받기·넘기기(한꺼번에 처리한 것은 하나로), 지난 검수 의견 뒤집기, 외부 번역 가져오기, 용어 바꾸기가 하나씩, 전체 번역 한 번, 검수 한 번, 채팅 한 턴이 각각 하나로 남습니다. 되돌리기(채팅 창의 "방금 변경 되돌리기": 채팅이 마지막에 고친 한 줄)도 "되돌리기 n줄"로 남아 다시 취소할 수 있고, 채팅 턴 안에서 되돌린 것은 그 턴에 합쳐집니다(같은 턴에 쓰고 되돌렸으면 남지 않음). 되돌릴 줄이 그 뒤에 다른 행동으로 다시 바뀌었으면 그 줄은 건너뜁니다. 앱을 닫아도 `history.json` 에 남고, 최근 200개만 둡니다. "이 행동만 취소"는 그 행동이 바꾼 줄을 그 전으로 되돌리되, 그 뒤에 다시 바뀐 줄은 그대로 두고 그 수를 알려 줍니다. "이 시점으로 되돌리기"는 그 뒤의 행동을 새것부터 모두 취소합니다(고른 행동은 남음). 줄마다 첫 바뀐 문장이 "원문 → 번역"으로 보이고(여러 줄이면 "외 n줄"), 줄을 누르면 바뀐 문장이 위치, 원문, 바꾸기 전 → 바꾼 뒤(달라진 부분에 색)로 펼쳐집니다. 한 번에 100줄씩 보이고 "외 n줄 더 보기"로 이어 보며, "이 문장 보기"는 텍스트 목록에서 그 항목을 엽니다(다시 추출해서 지금은 없는 문장은 꺼짐). 용어 바꾸기는 "용어 바꾸기: 옛 번역 → 새 번역 (n곳)"으로 남습니다. 취소한 행동은 "취소됨"으로 흐리게 남고 다시 취소할 수 없지만 펼쳐 볼 수는 있습니다. 용어집·판단·그림·이벤트 수정, 게임 업데이트가 옮긴 번역은 여기서 되돌리지 않습니다.

**"게임 실행"**은 가장 최근 빌드의 패치를 시험용 사본(`testplay/`)에 얹고 사본의 `Game.exe`(없으면 `nw.exe`)를 켭니다. 그림·소리·실행 파일은 원본과 하드 링크로 이어 복사 시간을 줄이고, 패치를 쓸 때는 사본 쪽 파일을 먼저 지우고 쓰므로 원본은 바뀌지 않습니다. 처음 한 번은 사본을 만드느라 오래 걸리고, 다음부터는 바뀐 파일만 다시 가져옵니다. 사본의 `save/` 는 덮어쓰지 않습니다.

### 10. 게임 업데이트

게임의 새 버전이 나오면 위 막대의 "새 버전 가져오기"에서 새 폴더를 고르거나 끌어다 놓습니다.

1. 확인: 엔진과 제목을 보여 주고 버전 이름을 제목이나 폴더 이름(`ver1.03`, `v1.2`, `1.0.3`)에서 채웁니다. 엔진이 다르거나 `data/*.json` 파일 이름이 절반도 겹치지 않으면 "다른 게임 같아요"라고 경고하고, "그래도 가져오기"를 체크해야 진행합니다. 지금 버전과 같은 폴더는 받지 않습니다.
2. 가져오기: 지금 파일을 `backups/before-<버전>/` 에 남기고, 새 원본의 추출과 비교를 모두 끝낸 뒤에 한꺼번에 바꿉니다. 도중에 실패하면 프로젝트는 그대로입니다.
3. 문장: 번역표의 열쇠가 원문에서 만든 id 라서, 원문이 그대로인 문장은 어디로 옮겨 가도 번역이 붙습니다. 같은 파일 안에서 75% 이상 비슷한 문장은 "바뀐 문장"으로 짝지어 이전 원문과 이전 번역을 붙입니다. 문장부호·공백만 다르거나 화자 줄의 이름만 다르면 이전 번역을 미리 채워 "검토 필요"로 둡니다. 사라진 문장의 번역은 번역표에 남습니다(문장이 되살아나면 번역도 되살아남).
4. 수정: 이벤트 목록이 그대로면 그대로 얹고, 앞뒤에 줄이 더해졌으면 커맨드 내용으로 맞춰 번호를 옮깁니다. 가리키던 줄이 없어졌거나 끼워 넣을 자리의 앞뒤가 바뀌었으면 충돌로 남기고, 결과 화면의 "Claude에게 맡기기"로 채팅에 넘길 수 있습니다.
5. 그림: 지시서가 있는 그림의 원본이 바뀌었으면 "원본이 바뀜"으로 표시됩니다.

결과는 "업데이트 결과"에서 다시 볼 수 있습니다. 텍스트 화면의 "바뀐 문장" 필터와 항목 탭의 "이전 버전의 문장" 상자("이전 번역 가져오기")로 고치고, 결과 화면의 "새·바뀐 문장 번역 맡기기"로 번역을 맡길 수 있습니다. 전체 번역은 바뀐 문장에 이전 번역을 참고로 실어 보냅니다.

"이 업데이트 되돌리기"는 가장 최근에 가져온 버전만 되돌립니다. 가져오기 직전의 파일로 되돌리고 그 버전의 원본 사본과 요약을 지웁니다(백업은 `backups/rolled-back-<버전>-<시각>/` 로 남김). 작업이 진행 중일 때는 가져오기와 되돌리기를 할 수 없습니다.

## 프로젝트 폴더에 생기는 파일

모든 JSON 은 UTF-8, 들여쓰기 2칸입니다. 처음 쓸 때 생기는 파일도 있습니다.

```
<프로젝트>/
  project.json            이름, 엔진, 게임 폴더, www/ 접두사, 버전 목록, 지금 버전
  original/v1/            가져온 원본 사본 (읽기만 함). 업데이트를 가져오면 v2/, v3/ … 이 더해짐
    data/*.json
    js/plugins.js, js/plugins/*.js
    files.json            img/, audio/, movies/ 아래 파일 목록
    index.html            게임의 index.html (제목 번역용)
    package.top.json      게임 최상위 package.json (창 제목 번역용)
    fonts/gamefont.css    MV 게임의 폰트 설정 (있을 때만)
  units.json              뽑은 문장(번역 단위)과 각 문장이 나오는 자리 목록
  extract.json            추출 설정: { extraStrings: 일본어가 없어도 뽑을 글자, extractorVersion: units.json 을 만든 추출기 버전 }. 추출기가 바뀐 뒤 프로젝트를 열면 다시 뽑음(번역표는 그대로)
  translations.json       번역표: 문장 id → { target, status, updatedAt, … }
  history.json            작업 기록: 번역표를 바꾼 행동 최근 200개 [{ id, at, origin, label, changes: [{ unitId, before, after }], undoneAt? }] (들여쓰기 없이 씀)
  glossary.json           용어집: { terms, characters, styleGuide, rules, confirmedAt }
  draft-notes.json        용어집 초안의 대본 읽기 메모
  decisions.json          판단 필요 결정: 판단 키(또는 unit:<id>) → { translate, keep, status, by, reason? }
  patches.json            이벤트 수정 등 원본 대비 바뀐 점
  preview.json            미리보기 설정: 게임 폰트 경로, 대사창 치수 고친 값(overrides), 창별 한 줄 너비·줄 수 고친 값(windows: { message?, help? }, 없으면 빠짐)
  images.json             그림 작업 지시서와 기본 폰트, 대상 폴더
  images/                 그림 목록 기억(catalog.json), 찍은 그림(rendered/), 썸네일(thumbs/), 직접 고친 그림(manual/)
  builds/NNN/
    patch/                패치에 들어간 파일 (게임 최상위 기준 경로, MV 배포판이면 www/…)
    manifest.json         { number, createdAt, version, files: [{ path, sha1 }] }
    <이름>_patch_NNN.zip
    snapshot.json         이 빌드에 들어간 것의 요약 (다음 빌드와 비교용)
    diff.json             지난 빌드와 비교한 숫자와 목록
    notes.txt             이 빌드의 패치노트
  backups/before-<버전>/  업데이트를 가져오기 직전의 프로젝트 파일 (되돌리기용)
  updates/<버전>.json     그 업데이트의 요약 (업데이트 결과 화면이 읽음)
  testplay/               게임 실행용 시험 사본 (.version, .patched.json)
```

## 채팅 도구

채팅의 Claude CLI 는 내장 도구(파일 읽기, 셸 등)를 모두 끄고 이 앱의 도구만 씁니다. Claude 에게 보이는 이름은 `mcp__mvmz__<도구>` 입니다.

| 도구 | 입력 | 하는 일 |
|---|---|---|
| `project_status` | 없음 | 프로젝트 이름, 엔진, 상태별 줄 수 |
| `search_units` | `query`, `status?`, `limit?`(기본 20, 최대 50) | 원문·번역·화자에서 글자 그대로 찾기. `status: overflow` 는 게임 창을 넘는 번역만 |
| `get_unit` | `id` | 한 문장의 자세한 정보와 검사 결과, 같은 파일 앞뒤 대사 각 2개 |
| `set_translation` | `id`, `target` | 번역 쓰기. 오류가 있으면 `error`, 없으면 `translated`. 창을 넘는 줄을 자동으로 나눴으면 나눈 글을 `rewrapped` 로 답함 |
| `set_status` | `id`, `status: approved \| needs-review \| translated` | 상태 바꾸기 |
| `undo_last` | 없음 | 채팅이 방금 고친 것을 통째로 되돌리기: 이번 턴에 고친 것, 없으면 아직 취소되지 않은 채팅의 직전 행동. 무엇을(행동 제목, 시각) 몇 줄 되돌렸고 몇 줄 건너뛰었는지와 앞의 5줄(위치, 원문 앞 30자)을 답함 |
| `glossary_search` | `query` | 용어와 인물 카드에서 찾기 |
| `glossary_set_term` | `source`, `target`, `category?`, `scope?` | 용어를 확정 상태로 저장. 번역이 바뀌면 번역문도 조사까지 맞춰 바꿈. `scope` 가 `speaker` 면 화자 이름 자리에만, `name` 이면 이름으로 쓰인 곳에만 적용 |
| `list_decisions` | `query?` | 판단 필요 묶음 목록 |
| `set_decision` | `key`, `translate`, `mode?`, `from?`, `dropLast?`, `reason?` | 판단을 바로 확정. 모르는 키는 실패 |
| `list_actions` | 없음 | 작업 기록의 최근 행동 10개(id, 시각, 출처, 제목, 줄 수, 취소됐는지) |
| `cancel_action` | `id` | 작업 기록의 행동 하나만 취소(출처와 상관없이. 그 뒤에 다시 바뀐 줄은 그대로). 답은 `undo_last` 와 같은 꼴 |
| `event_files` | 없음 | 이벤트가 있는 파일 목록 |
| `event_list` | `file` | 한 파일의 이벤트 목록(맵은 페이지마다)과 조건, `listPath` |
| `event_read` | `file`, `listPath`, `raw?`, `from?`, `to?`, `version?` | 이벤트를 풀어쓴 글과 해시. `raw` 면 그 범위의 원본 커맨드(최대 30줄), `version` 이면 옛 버전의 이벤트 |
| `usage_search` | `type`(switch, variable, commonEvent, item, picture), `id` | 어디서 켜지고 읽히는지. 페이지 조건은 `index: -1` |
| `event_patch` | `title`, `file`, `listPath`, `baseHash`, `ops`, `note?`, `originalBug?` | 원본 번호 기준의 수정을 더함. 같은 목록에 수정이 있으면 그 수정을 바꿈 |
| `set_josa_plugin` | `enabled` | 조사 자동 맞춤을 켜고 끔. 상태와 부딪힐 수 있는 게임 플러그인 이름을 답함 |
| `image_sheet` | `folder?`, `status?`, `page?` | 번호 붙은 썸네일 모음판 1장(20개)과 목록 |
| `image_view` | `file`, `which?: original \| rendered` | 그림 1장(긴 변 1,568px 이하)과 크기, `scale`, 영역 |
| `image_set_recipe` | `file`, `regions`, `done?` | 그림의 지시서를 통째로 바꿈. 목록에 없는 `fontPath` 는 무시 |
| `image_set_status` | `file`, `status: todo \| done \| skip` | 그림 상태 바꾸기 |
| `image_list` | `status?`, `folder?`, `limit?`(기본 50, 최대 200) | 그림 목록(글만) |
| `update_summary` | 없음 | 가장 최근 게임 업데이트의 요약과 충돌난 수정 목록. 업데이트가 없으면 실패 |
| `find_game_text` | `text` | 지금 원본 사본에서 글자 전체가 같은 문자열을 찾음(읽기만). 플러그인 설정 값·열쇠 이름(플러그인, 설정 이름), 플러그인 JS 문자열(파일, 머리말 주석 제외), data 파일(파일, 개수)과 이미 번역 항목인지. 세 글자 이상이면 그 글을 일부로 품은 data 문자열(파일, 어느 항목의 어느 칸, 메모란이면 태그 블록)과 플러그인 설정 값도 앞뒤 30자와 함께 줌. 최대 10곳 |
| `add_extract_text` | `text` | 일본어가 없는 글자를 번역 항목으로 넣음. 플러그인 설정에 있을 때만 `extract.json` 에 적고 다시 뽑음. 없으면 넣지 않고 어디 있는지만 답함 |
| `set_text_window` | `window: message \| help`, `chars?`, `fits?`, `px?`, `maxLines?`, `withFace?` | 창의 한 줄 너비를 한글 글자 수, 게임에서 딱 맞게 들어간 글, px 가운데 하나로 정함(프로그램이 게임 폰트로 재서 px 로 바꿈). `withFace` 면 얼굴 그림 옆에서 잰 길이. 정해진 px, 한글 약 n자, 지금 넘치는 줄 수와 그 가운데 자동으로 고칠 수 있는 수를 답함 |
| `rewrap_overflow` | `window?` | 창을 넘는 번역의 줄바꿈 자리를 한 번에 다시 맞춤. 고친 수, 못 고친 수와 그 id 최대 10개, 이유별 수를 답함 |

## 명령줄 도구

앱 없이 핵심 기능을 쓰는 도구입니다. `npm run build` 로 `dist/cli.js` 를 만든 뒤 `node dist/cli.js <명령>` 으로 부릅니다.

| 명령 | 하는 일 | 출력 |
|---|---|---|
| `mvmz import <gameDir> <projectDir> --name <이름>` | 게임 판별, 프로젝트 만들기, 원본 복사, 전체 추출 | 엔진, 문장 수, 판단 필요 수, 경고 |
| `mvmz export <projectDir> --out <file> [--all]` | 미번역 문장을 JSON 배열로 저장. 판단 필요는 `--all` 일 때만 | 내보낸 수 |
| `mvmz apply <projectDir> <file>` | `[{ id, target }]` 를 번역표에 넣고 저장 | 넣은 수, 모르는 id |
| `mvmz check <projectDir>` | 형식 검사. 오류인 문장은 상태를 `error` 로 저장 | 문제 목록. 오류가 있으면 종료 코드 1 |
| `mvmz build <projectDir>` | 검사 뒤 바뀐 파일만 묶은 패치 zip | zip 경로, 파일 목록, 건너뛴 오류 수 |
| `mvmz status <projectDir>` | 상태별 개수 | 전체, 미번역, 번역 완료, 검토 필요, 승인, 오류 |
| `mvmz unpack <exe> <outDir>` | exe 하나로 뭉쳐진 게임(Enigma Virtual Box)을 빈 폴더에 풀기. exe 는 읽기만 함 | 파일 수, 크기 |

종료 코드: 0 성공, 1 오류(메시지 한 줄), 2 모르는 명령이나 인자 부족(사용법 출력).

## 배포용으로 묶기

```bash
npm run dist
```

`release/` 에 설치 파일(NSIS)과 zip 이 나옵니다. 설정은 `electron-builder.yml` 입니다. 서명 인증서가 없어 서명하지 않으므로, 처음 실행할 때 윈도우가 경고할 수 있습니다.

## 개발과 시험

```bash
npx vitest run
```

```bash
npx tsc --noEmit -p tsconfig.node.json
```

```bash
npx tsc --noEmit -p tsconfig.web.json
```

```bash
npm run build:app && npm run test:e2e
```

- 단위 시험은 `tests/` 에 `src/` 와 같은 구조로 있고, 시험용 작은 게임은 `tests/helpers/miniGame.ts` 가 만듭니다. `tests/e2e` 는 빌드된 앱을 실제로 띄웁니다(먼저 `npm run build:app`).
- 실제 Claude CLI 를 쓰는 시험은 `MVMZ_REAL_CLI=1` 일 때만 돌고 토큰을 씁니다(가장 싼 모델, 시험용 작은 게임만): `tests/main/realCli.test.ts`(채팅, 먼저 `npm run build:app`), `realCliJson.test.ts`(정해진 형식의 답), `realDecide.test.ts`(판단 추천), `realFlow.test.ts`(초안 → 확정 → 번역 → 검수), `realEventPatch.test.ts`(이벤트 수정), `realImageTool.test.ts`(도구 결과의 그림), `tests/e2e/realImage.e2e.test.ts`.
- 연기 시험은 `MVMZ_` 로 시작하는 환경 변수로 파일 고르기 창이나 CLI 를 대신합니다: `MVMZ_PICK_DIR`, `MVMZ_PICK_DIR2`(새 버전 폴더), `MVMZ_PICK_FONT`, `MVMZ_PICK_PNG`, `MVMZ_SAVE_FILE`, `MVMZ_OPEN_FILE`, `MVMZ_FONT_DIRS`, `MVMZ_CLAUDE_COMMAND`, `MVMZ_CLAUDE_JSON_COMMAND`(가짜 CLI `tests/fixtures/fake-claude-json.mjs`), `MVMZ_GAME_SPAWN_FAKE`(게임을 실제로 띄우지 않음), `MVMZ_TEST_HOOKS`, `MVMZ_USER_DATA`.

## 문제 해결

| 보이는 것 | 할 일 |
|---|---|
| "Claude CLI를 실행할 수 없습니다" / 상태 줄 "Claude CLI 없음" | Claude CLI 를 설치하거나, 설정의 "Claude CLI" 에 `claude.exe` 경로를 넣습니다. 채팅 탭의 "다시 확인"으로 다시 찾습니다 |
| "로그인이 필요합니다" / 상태 줄 "로그인 필요" | 터미널에서 `claude` 를 실행해 로그인합니다 |
| "용어집을 먼저 확정하세요" | 용어집 화면에서 "용어집 확정"을 누릅니다 |
| "다른 작업이 진행 중입니다" | 번역·검수·추천 같은 작업은 한 번에 하나만 됩니다. 위의 작업 막대에서 끝나기를 기다리거나 멈춥니다 |
| "사용량 한도 때문에 멈췄어요" | Claude 사용량이 회복된 뒤 "이어하기"를 누릅니다. 끝난 묶음은 다시 보내지 않습니다 |
| "바뀐 파일이 없습니다" (빌드) | 패치에 넣을 번역·수정·그림이 아직 없습니다. 오류 상태인 번역은 들어가지 않습니다 |
| "먼저 패치를 빌드하세요" (게임 실행) | 게임 실행은 가장 최근 빌드를 씁니다. "패치 빌드"를 먼저 합니다 |
| "게임 폴더를 찾을 수 없습니다" | 게임 폴더를 옮기거나 지웠습니다. 게임 실행과 그림, 폰트는 원래 게임 폴더를 읽습니다 |
| "MV/MZ 게임이 아닙니다" | `data/System.json` 이 있는 폴더(MV 배포판은 그 위 폴더)를 고릅니다. exe 하나로 뭉쳐진 게임은 "풀고 계속" 버튼이 나옵니다. 버튼이 안 나오면 Enigma Virtual Box 가 아닌 다른 방식으로 묶인 게임입니다 |
| 폰트 목록에 원하는 폰트가 없음 | `.ttc` 모음 파일은 쓸 수 없습니다. `.ttf`/`.otf` 파일을 "폰트 파일 직접 고르기"로 고릅니다 |
| 소스에서 실행할 때 `node` 나 `claude` 를 못 찾음 | `C:\Program Files\nodejs` 와 Claude CLI 설치 폴더를 PATH 앞에 붙입니다 |
